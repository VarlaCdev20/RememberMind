# Revisión y aceptación

## Por ficha

1. Confirmar fuente y alcance; localizar decisiones ya adoptadas.
2. Contrastar ruta, clase, vista, datos y acciones realmente conectados.
3. Revisar cada capacidad por rol con autorización y efectos en backend.
4. Comparar diseño requerido e implementación sin aprobar nuevas reglas por descripción.
5. Añadir positivos, negativos y límites; enlazar pruebas ejecutadas o marcar pendientes.
6. Verificar enlaces y versión; registrar revisión visual aparte cuando corresponda.

## Estados independientes

- Documentación preparada/completa en su alcance.
- Implementación localizada.
- Verificación técnica ejecutada.
- QA visual ejecutada.
- Validación clínica cuando corresponda, con evidencia identificada.

Completar un documento no completa el software. La ausencia de QA o una decisión nueva limita su alcance; no detiene todo el desarrollo autorizado. [Estado actual del producto](../../ESTADO_ACTUAL.md).
