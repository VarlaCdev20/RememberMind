# Propósito

Definir una experiencia serena, humana, acogedora, profesional y premium, con alertas clínicas claras. Entregar dirección artística que la skill de Design System pueda traducir.

# Cuándo usar

Dirección visual de dashboards, formularios, shell, directorios, cards, vistas clínicas, administrativas o familiares.

# Cuándo NO usar

Implementación de tokens/componentes, modificación de proceso o invención de gravedad clínica. Marketing general conserva sus auxiliares.

# Fuentes que debe consultar

Leer el [contrato compartido](../../../docs/frontend/CONTRATO_VISUAL_UX_UI.md) al iniciar una tarea de esta especialidad; reutilizarlo si ya se leyó. El [pipeline](../../../docs/frontend/STACK_SKILLS_UX_UI.md) determina orden y selección, sin cargar etapas ajenas.

Leer la paleta, tipografía y escalas objetivo del contrato compartido. Inspeccionar evidencia visual aprobada y Design System actual, registrando diferencias entre objetivo e implementación.

# Workflow obligatorio

1. Partir del UX FLOW y referencia aprobada cuando existan; identificar escena de uso, densidad y jerarquía.
2. Especificar superficies neutrales, sage/earth tones y acentos clínicos funcionales. Consumir [el brief artístico](references/art-direction.md).
3. Asignar las nueve funciones tipográficas y profundidad 0–4. Justificar cada aplicación de glass soft/elevated.
4. Definir apariencia de botones físicos digitales, cards y estados. Mantener critical fuerte y distinguir acciones destructivas de alertas clínicas.
5. Entregar la especificación y las diferencias respecto al producto para implementación compartida; verificar legibilidad de propuestas sin atribuirles aprobación automática de contraste.

# Reglas no negociables

Aplicar gobernanza de BDD, terminología, autoridad visual y UX GAP DETECTADO del contrato común. Reference-first cuando hay imagen aprobada. Calidez sin infantilización ni reducción de percepción crítica. No cambiar paleta por preferencia ni pintar toda una pantalla según el rol.

# Criterios UX

Jerarquía visible, densidad operativa, profundidad coherente, sombras cálidas, contraste y relieve sutil. Blanco/negro puros no dominan. El glass tiene propósito y fallback.

# Errores frecuentes que debe evitar

SaaS genérico, hospital azul frío, minimalismo vacío, plantas/ilustraciones decorativas repetidas, pasteles ilegibles, sombra negra pesada, cards verdes por estado normal, cuatro familias tipográficas sin jerarquía.

# Definition of Done

Especificación define superficies, funciones tipográficas, niveles de profundidad, glass, botones y representación de estados. Respeta referencia y separa valores objetivo de tokens ya implementados.

Informar ANTES, PLAN, IMPLEMENTACIÓN y VERIFICACIÓN según el alcance; distinguir lo comprobado de lo pendiente.
