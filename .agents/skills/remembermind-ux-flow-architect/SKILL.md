# Propósito

Definir qué necesita lograr cada rol y cómo continúa su trabajo. Entregar UX FLOW antes de decidir colores, componentes o disposición definitiva.

# Cuándo usar

Dashboards, sidebars, headers operativos, directorios, formularios y procesos cuya prioridad o continuidad cambia.

# Cuándo NO usar

Retoque de CSS, reproducción estética aislada o decisiones nuevas sobre admisión, competencia profesional o permisos.

# Fuentes que debe consultar

Leer el [contrato compartido](../../../docs/frontend/CONTRATO_VISUAL_UX_UI.md) al iniciar una tarea de esta especialidad; reutilizarlo si ya se leyó. El [pipeline](../../../docs/frontend/STACK_SKILLS_UX_UI.md) determina orden y selección, sin cargar etapas ajenas.

Consultar rutas, navegación, Policies, documentación funcional y consultas del flujo. Usar la arquitectura vigente; no deducir tareas de las columnas de una tabla.

# Workflow obligatorio

1. Identificar rol, objetivo, entrada y capacidades reales. Separar tareas frecuentes, urgentes y decisiones; confirmar qué información está autorizada.
2. Examinar el recorrido previo y posterior. Identificar contexto que debe permanecer visible, acción primaria, secundarias y recuperación tras error.
3. Reducir pasos redundantes sin omitir revisiones, confirmaciones o invariantes institucionales. Hacer visibles las dependencias de datos o decisiones pendientes.
4. Entregar UX FLOW con [el formato y casos por rol](references/ux-flow.md) antes de editar. Acordar la jerarquía con el contrato o instrucciones existentes; no pedir aprobación para rutina técnica autorizada.
5. Tras implementar un flujo autorizado, verificar entrada, salida, excepciones y siguiente acción; transferir especificación de jerarquía a las etapas visuales.

# Reglas no negociables

Aplicar gobernanza de BDD, terminología, autoridad visual y UX GAP DETECTADO del contrato común. Conservar admisión formal, contexto del residente, autoría y continuidad. UI por rol no crea privilegios. Si existe referencia aprobada, preservar su composición en las etapas visuales y señalar ajustes necesarios para el flujo.

# Criterios UX

La persona sabe dónde está, qué requiere atención, qué acción priorizar y qué sucederá después. Información secundaria puede plegarse; el contexto necesario para decidir permanece accesible.

# Errores frecuentes que debe evitar

Diseñar primero una tabla; presentar todas las acciones con el mismo peso; ocultar alertas persistentes; terminar en Guardar sin resultado ni continuidad; asumir que todas las personas trabajan con el mismo menú.

# Definition of Done

UX FLOW identifica objetivo, usuario, entrada, pasos, excepciones, salida y siguiente acción natural, con fuentes verificadas. No cambia reglas institucionales para reducir clics.

Informar ANTES, PLAN, IMPLEMENTACIÓN y VERIFICACIÓN según el alcance; distinguir lo comprobado de lo pendiente.
